# 採集品質間隙修正（2026-10-21）

手機看到震動及聲音波紋，表示收到強度資料；訓練還會檢查 IMU 取樣是否連續。波紋有反應並不能證明資料足以建立模型。

## 已查證的原因與修正

手機保存的最新失敗資料：目標採集 8.16 秒收到 54 包、遺失 0，但 53 包標記取樣間隙，暖機後 28 個視窗全部品質不良。背景採集也有同樣問題。這次並非單純敲擊不足或藍牙封包遺失。

原韌體直接在 IMU 取樣主迴圈呼叫 Bluefruit `notify`；BSP 1.1.13 的該函式會等待 HVN 傳送 semaphore。聲音及特徵通知同時傳送時，可能阻塞 IMU 讀取。新版改為 32 筆有界通知 FIFO，透過 SoftDevice 非阻塞 API 傳送；無可用空間就留待下個迴圈，繼續取樣。特徵順序與最後採集完成狀態保持 FIFO 順序；預覽音量可合併，斷線 session 過期資料不會傳到新連線。

MTU 仍為 23、封包仍最多 20 bytes，增加 HVN 佇列至 4 並請求 15–30ms 連線間隔。未修改 BSP 全域程式庫，也未放寬品質門檻。手機現在分別顯示背景與敲擊的接收、間隙、飽和與遺失數，不再一律要求重新連線。

## 實際驗證

- 真實 iPhone BLE 連接 XIAO，採集特徵並同時傳送 PDM 音量。
- 4.40 秒採集收到 104 個視窗，暖機後有效 78 個；取樣間隙 0、遺失 0，品質通過。
- 同輪收到 42 筆音量波紋資料，麥克風有效；剩餘與累計計數不變。
- XIAO 已更新應用韌體、正常重啟，原計數保留；手機新版已安裝並正常啟動。
- 42 項 Swift 測試通過；新增實際 54 包／53 間隙案例，確認仍拒絕不連續資料。
- Store 的 25 項計數／同步檢查及 8 項採集／即時波紋整合檢查通過。
- 通知 FIFO 的滿載、合併、順序、session 隔離測試通過 AddressSanitizer 與 UndefinedBehaviorSanitizer。
- iPhone 與 watchOS App 編譯通過；本次未更新實體手錶。

這次實機測試驗證連續採集與傳輸品質，沒有替使用者敲擊建立模型，也未驗證真實 BB 擊發辨識率。

## 現在操作

手機進入「採集訓練」，按「開始訓練」或「重新訓練」。先安靜 4 秒；綠燈提示後等 1 秒，再在板子旁每秒敲一次，敲 3–5 次。板邊用少量絕緣膠帶固定，USB 線留鬆弛，不直接敲開發板。收足後按「套用並啟用自動計數」，再核對敲擊與累計推估數。

機械震動特徵用於計數；麥克風音量波紋目前僅作觀察。
