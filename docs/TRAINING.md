# 自適應底噪採集與即時波紋

目前使用原版 Seeed XIAO nRF52840 Sense 的 **IMU + 內建 PDM 麥克風**。手機不使用自己的麥克風。音訊只在板上暫存並計算音量包絡，不保存或傳送音檔。

## 新手操作

1. 用絕緣膠帶少量固定開發板邊緣在同一張桌面，USB 線留鬆弛。不要直接敲裸露開發板。
2. 手機開啟「採集訓練」。「即時監看 · XIAO」會顯示震動峰值曲線與麥克風音量強度曲線。這是強度包絡，不是原始音訊 PCM 或 416Hz 原始震動波形。
3. 按「開始訓練」，先讓桌面安靜 **4秒**，量測底噪。這一步不用輕移或輕碰桌面。
4. 綠燈提示敲擊後，等1秒，再於開發板旁敲桌面3–5次，每次隔約1秒。目標採集最多8秒；至少4秒且找到3個峰值群組就提前分析。
5. 紅燈時手機分析。少量有效事件會保留底噪、只補收目標；完全沒有高於底噪的訊號或資料品質異常則停止並顯示原因，不反覆盲收。
6. 完成後按「套用並啟用自動計數」，等待模型保存與啟用確認。可隨時停止訓練或關閉即時監看。

若聲音曲線有反應、震動曲線卻幾乎沒變化，聲音已到達麥克風，但機械震動可能沒有良好傳到板子。先調整固定、讓線鬆弛並在板子旁敲；不用刻意大力敲，也不要敲板子。

## 修正的採集方法

舊版先以固定0.03g和韌體候選旗標篩選訓練事件，輕敲可能在建立模型前就被排除。新版先收完整16樣本視窗特徵，排除暖機、飽和和異常間隙，再由手機估計底噪中位數與MAD，建立具有1mg傳輸量化裕量的自適應門檻。

相隔不超過200ms的高於門檻視窗合併成同一個峰值群組，避免一次敲擊的餘震被當成多個訓練事件。韌體候選旗標在採集階段只作診斷，不能刪掉訓練資料。模型門檻可低至0.002g；實際由底噪決定，不保證任何特定弱震動都可可靠分類。

快速模式至少3個目標事件、30個背景有效視窗。背景與目標相似可完成，但提醒容易誤計數。目標保留樣本辨識率仍需至少80%；只有3個事件時保留樣本可能僅1個，並非可靠的真實準確率估計。傳輸遺失超過5%或非暖機視窗品質不良超過10%拒絕分析。

## 即時監看與隱私

XIAO 原版 PDM 麥克風：BSP D19/P1.10供電、D20/P1.00時鐘、D21/P0.16資料；16kHz單聲道。每100ms只傳送RMS／峰值音量和最近的IMU峰值。聲音只供觀察，計數分類仍使用IMU模型，不宣稱已做槍聲辨識。

監看由目前客戶端擁有20秒租約，手機在前景定期續期；採集期間也提供波紋。離開頁面、App離開前景、斷線、租約到期或安全鎖定會停止麥克風。只有聲音強度數字被傳輸，RAM中的PCM循環緩衝不保存到Flash。

## 已驗證與限制

42項Swift測試、25項原有Store整合檢查與8項自適應／即時波紋整合檢查通過。實體XIAO的4秒測試取得約6.4萬個音訊樣本和104個IMU視窗（78個暖機後有效，無間隙／飽和）；iPhone經真實BLE接收到28筆有效音量／震動資料。

上述只驗證取樣與資料傳輸，沒有驗證實際BB發射或使用者這次敲擊的準確率。取得實體設備、更換安裝位置或固定方式後重新採集。所有剩餘與累計數皆為推估，保留手動校正；重新裝填不清除累計。
